# AGENTS.md — как работать с ИИ над этим проектом

Этот файл — инструкция для ИИ-ассистента (и памятка для автора), а не набор готовых шаблонов кода.

## Что это за проект

Verde Marea — локальная система бронирования столов (учебный проект). Полная легенда, роли и сценарии — в README.md; визуальная система — в design.md.

## Жёсткие правила (не нарушать)

1. Работать строго по этапам. Этап начинает автор командой «Этап N. …». Не забегать вперёд и не выдавать «всё решение целиком».
2. Формат ответа на этап: краткий план (5–10 строк) → файлы целиком с путями → команды отдельным блоком → чек-лист проверки.
3. Стек фиксирован: Next.js (App Router) + React + TypeScript, Tailwind CSS, Zod, PostgreSQL (локальный), Prisma, bcryptjs (12 раундов), npm. Не менять.
4. Без внешних интеграций и публичного деплоя. Не предлагать их.
5. Не добавлять библиотеки без явного вопроса автору.
6. Код — TypeScript, с типами, без `any`, с комментариями на русском в ключевых местах.
7. Пароль — только `passwordHash` (bcryptjs, 12 раундов); `passwordHash` не возвращать в UI и API.
8. Все критические проверки — на сервере (правила окон, отмена за 3 часа, права ролей, занятость столов).
9. Если автор просит что-то против ТЗ (например, хранить пароль открытым текстом) — отказаться и напомнить правило.

## Как ИИ должен планировать

- Перед крупным этапом — предложить разбить на подшаги, если задача большая.
- Сверяться с README.md (домен, роли, сценарии) и design.md (токены, компоненты) — не выдумывать цвета, статусы или роли заново.
- При работе с БД — менять схему только через `schema.prisma` и миграции.
- Не оставлять непонятных TODO; каждый артефакт должен быть проверяемым по чек-листу.

## Что не нужно в этом файле

Готовые шаблоны кода, полные тексты моделей или компонентов — они появляются по мере этапов. Здесь — только рамки и правила.
